## Telegram

Нужны один выделенный тестовый бот и одна закрытая группа «myit D4 — тестовые заявки» под контролем владельца.
Владелец создаёт бота через BotFather, добавляет в группу и разрешает отправку сообщений/фото.
Администраторские права, чтение истории, выключение privacy mode и webhook этому исходящему тесту не требуются.
Один неизменяемый получатель задаётся сервером; посетитель не передаёт chat_id или URL.
Bot token — авторизация бота, а не узкий доступ только к одной группе; границу получателя обеспечивает наш сервер.
Основание: [управление ботом](https://core.telegram.org/bots/features#botfather),
[sendPhoto](https://core.telegram.org/bots/api#sendphoto).

Безопасная передача: token помещает владелец в отдельный Keychain item или исключённый `.env` D4,
без вставки в чат, команды, README или Git. Получателя задаёт там же. Имена будущих параметров:
`D4_TELEGRAM_TOKEN`, `D4_TELEGRAM_CHAT_ID`; фактических значений в коде нет.
Backend не использует токен существующих ботов/других демо. Следующая проверка потребует отдельного
разрешения на чтение конкретного локального секрета и отправку именно в эту группу.

Предлагаемый ограниченный live-тест: одна синтетическая заявка, один подготовленный перекодированный JPEG,
один sendPhoto с короткой подписью и submission_id. Не публиковать URL фото — передавать байты.
Владелец подтверждает видимость сообщения/ID в группе; ответ API сохраняется только как обезличенное свидетельство.
Таймаут после отправки → unknown, без автоматической повторной отправки до проверки полученного ID.

## Google Sheets

Нужны:

- Управляемый владельцем Google-аккаунт и отдельная пустая таблица **myit D4 demo registry**, лист **Leads**.
- Выделенный Cloud-проект с включённым Sheets API и отдельный service account только для этого стенда.
- Доступ Editor к **этой таблице** для email service account. Другие файлы ему не предоставлять.
  Project-level Owner/Editor, domain-wide delegation и доступ к личному Drive не нужны.
- Серверная авторизация service account в Keychain/согласованном секретном хранилище среды;
  JSON/private key не передавать в чат, аргументы или репозиторий. Публичная часть (email) не заменяет закрытый ключ.

Предлагаемый OAuth scope — `https://www.googleapis.com/auth/spreadsheets`.
Он относится ко всему доступному spreadsheet, а не одному листу: поэтому используем отдельный service account
с доступом только к отдельной демо-таблице; листы с реальными данными туда не добавлять.
Сервер фиксирует spreadsheet_id и диапазон `Leads!A:I`, посетитель не управляет ни одним из них.
Основание: [scopes Sheets](https://developers.google.com/workspace/sheets/api/scopes),
[service-account OAuth](https://developers.google.com/identity/protocols/oauth2/service-account).

Колонки: submission_id, accepted_at_utc, sofa, size, material, description, synthetic_channel,
synthetic_contact, photo_count. Одна запись `values.append` с `valueInputOption=RAW`, затем чтение строки
с тем же submission_id для подтверждения. Фото/ключ квитанции/секреты/публичные ссылки на оригиналы в таблицу не пишутся.
API-права используются только для этой заявки/таблицы, не для инвентаризации личного Drive.
Метод: [append](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/append).

Аутентификационный SDK Google не входит в текущие 24 пакета. Перед этапом B потребуется отдельная проверка
необходимого минимального набора и согласование новых зависимостей. Сейчас он не установлен.
Включение платных сервисов, привязка billing и платные вызовы не предлагаются в этом разрешении.
