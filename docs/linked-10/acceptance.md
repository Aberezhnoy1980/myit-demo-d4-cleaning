## Правки по ревью

- У связанных заданий, которые обработчик берёт из `mock_queued`, одна попытка. Если адаптер после 429 предлагает повтор,
  обработчик сохраняет `mock_failed` сразу. Квитанция сообщает «Доставка не состоялась. Повтора не будет.»
  Второй канал завершается независимо. Ручные вызовы сохраняют существующий лимит и задержку.
  Прежний `mock_pending` не содержит признака связанного прогона, поэтому такие записи не переклассифицируются.
- Квитанция старой команды `simulate --channel sheets --scenario success` сообщает об имитации.
  Подтверждение сверки девяти полей остаётся у результата адаптера Sheets.

## Изменения

- `server/app.py` принимает пару тестовых адаптеров через явный аргумент `test_delivery`.
  После коммита новой заявки ответ возвращает UUID и ожидание по обоим каналам. Фоновая задача получает этот UUID
  и вызывает два существующих обработчика по очереди. Ошибка первого вызова оставляет второму свой запуск.
  Повтор с тем же ключом и данными получает прежний номер. Фоновая задача создаётся только при новом сохранении.
- `server/store.py` создаёт два задания ожидания в той же транзакции, что и заявку с фотографиями.
  При старте тестовое задание, прерванное до начала обработки, получает отказ. Задание, которое уже начали
  обрабатывать, получает неопределённый результат. Новые задания берутся по UUID из ответа сохранения.
- `server/sheets_auth.py` использует service account Google SDK с искусственным ключом и подставным OAuth-транспортом.
  На одну операцию Sheets разрешён один обмен токена. В `server/sheets.py` действует существующий контракт B2
  с RAW, поиском UUID, проверкой диапазона и чтением всех девяти полей для подтверждения результата.
- `server/telegram.py` берёт обработанный JPEG из SQLite и отправляет в подставной транспорт номер и параметры дивана.
  Синтетический контакт присутствует в девяти полях Sheets.
- `public/app.js` показывает «Запрос сохранён» и две отдельные строки. Для каждого канала видны ожидание,
  подтверждение, отказ или неопределённость. Подставные результаты имеют отметку тестового режима.
  «Проверить квитанцию» читает актуальные статусы по существующему ключу квитанции.

Обычный запуск создаёт задания со статусом «канал выключен». Для связанного теста нужны три MockTransport
и явная передача адаптеров в фабрику приложения. Подготовка ключа, создание заявки и перезапуск используют временный SQLite.
Живой прогон и съёмка согласуются отдельно.

Сетевой кабель VM отключался на время загрузки и тестов. Внутри отдельного сетевого пространства
проверяется наличие только `lo`. Исходные файлы из архива сверены с рабочими файлами.

| Сценарий | Проверяемый результат |
|---|---|
| Две новые заявки | На каждый номер по одному сообщению и одной строке. JPEG совпадает с обработанным фото из SQLite. В сообщении есть номер и параметры дивана, контакт остаётся в Sheets. Все девять значений совпадают после чтения. Старая заявка остаётся без доставки. |
| Повтор и перезапуск | Повтор возвращает HTTP 200, прежний номер и сохранённые статусы. Новых вызовов Telegram, OAuth и записи Sheets нет. |
| Отказ Telegram | Sheets подтверждает строку независимо от отказа Telegram. |
| Отказ Sheets | Telegram подтверждает сообщение независимо от отказа Sheets. При отказе OAuth выполняется один обмен, обращений к Sheets нет. |
| Тайм-аут после записи | Подставная таблица уже содержит строку. Статус Sheets неопределённый, повтор формы и перезапуск сохраняют одну строку. |
| Несовпадение при чтении | Изменение одного поля после append не даёт подтвердить строку. |
| Прерванные задания | Ожидавшее задание получает отказ, начатое получает неопределённый статус. Новых вызовов нет. |
| 429 от Telegram | Окончательный отказ Telegram и подтверждённая строка Sheets. Повтор формы после перезапуска сохраняет квитанцию и счётчики вызовов. |
| 429 от Sheets | Окончательный отказ Sheets и подтверждённое сообщение Telegram. После перезапуска повтор формы не вызывает каналы, таблица пуста. |
| Старая имитация Sheets | Команда `simulate` со сценарием `success` формирует квитанцию об имитации. Связанный прогон сохраняет формулировку о сверке. |

В первой ревизии лимит отправок увеличен только в тесте с шестью отправками формы за минуту,
чтобы проверить HTTP 200 и прежний номер после перезапуска.
