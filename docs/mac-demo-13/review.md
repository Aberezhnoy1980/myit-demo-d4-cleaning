## Почему отдельный провайдер Mac

Фактическое окружение: Intel Mac, macOS 15.8.2, Python 3.11.8, SQLite 3.45.1, LibreSSL 3.3.6, Node 22.14.0. Все 24 установленных пакета совпадают с ранее согласованным lock; `google-auth`, `cryptography`, `requests` отсутствуют. Новых установок нет. Прежнее исследование зависимости актуального SDK и Intel Mac остаётся историческим документом B2; Linux SDK не переносился и не подменялся старыми версиями.

Для ограниченного одного прогона добавлена подпись RS256 системным инструментом. [Протокол Google service account](https://developers.google.com/identity/protocols/oauth2/service-account) описывает HTTP/JWT-путь, но рекомендует готовые библиотеки из-за сложности безопасной реализации. Это **новая область независимого ревью**, не утверждение о полной эквивалентности SDK или готовности производственного сервиса.

Локально проверяются структура ключа, соответствие service account/фиксированному endpoint, целостность RSA и размер 2048–4096 бит. JWT имеет фиксированные alg/aud/scope, срок 300 секунд. Секрет передаётся только через stdin/анонимный pipe, не argv/временный файл. Процесс имеет пустое окружение с `OPENSSL_CONF=/dev/null`; вывод и исключения скрыты. Обмен OAuth — один POST, без redirect/proxy/retry, с ограничениями времени/размера/кодирования ответа и формата токена. Возвращённый bearer живёт только в памяти операции Sheets. Реальные файлы `.env`, `.env.sheets` и ключ не читались; конфигурационные тесты используют временный каталог и искусственный RSA-ключ.

На этой стадии не проверялись настоящая учётная запись, доступы, TLS/ответы Google/Telegram и пригодность реального ключа. Разрешение live не следует из прохождения офлайн-тестов.

