# D4 · план одного прогона на Mac

Срез `d4-divan-v-poryadke-mac-demo-13`, этап 1. Это инструкция для будущего согласования; ни живой запуск, ни запись сейчас не выполнялись.

## Что подтвердить до запуска

1. Независимый ревьюер принимает этот отдельный вход Mac и новый OAuth-провайдер. Владелец отдельно разрешает **один конкретный прогон и его запись**. Повтор и репетиция с отправкой требуют нового решения.
2. Владелец подтверждает отдельный закрытый тестовый Telegram-чат и бота с правом отправить фото именно туда. В чате не должно быть посторонних участников и данных. Значения токена и адресата передаются только в приватный файл, не в переписку/команду/документ.
3. Владелец подтверждает отдельную Google-таблицу, техническую учётную запись service account и включённый Sheets API в её проекте. Учётной записи достаточно редакторского доступа к этой таблице; доступ ко всему Drive, публичная ссылка, делегирование домена и права администратора не нужны. Нужен пустой лист `Leads`, только шапка `A1:I1`:

   `submission_id | accepted_at_utc | sofa | size | material | description | synthetic_channel | synthetic_contact | photo_count`

   До запуска владелец вручную проверяет порядок колонок, отсутствие объединений/формул/посторонних данных и право читать/дописывать строку. Программа дополнительно проверяет шапку, затем записывает `RAW` и читает все девять полей обратно.
4. Владелец выбирает безопасное синтетическое фото без лиц, геоданных и документов, описание и контакт `demo@example.test` либо `@demo_test`. Telegram получит **первое обработанное JPEG**, UUID и форму/число мест/обивку; контакт и описание туда не передаются. В таблице будут все девять полей, включая синтетический контакт и число фото, но не файл фото. Для съёмки использовать одно фото.
5. Согласовать кадр и маски: скрыть имена/аватары аккаунтов, название/адресата чата, имя бота и его URL, адрес таблицы/ID, email учётной записи, вкладки/закладки/уведомления. Приватные файлы, терминал с конфигурацией и инструменты разработчика в кадр не попадают. Показать можно UUID заявки, вымышленные поля и тестовое фото.

На этапе 1 ресурсы, доступы и настоящие ключи не проверялись и не создавались. Подтверждение владельца об исходных четырёх промптах Runway и принятых материалах сохранено прежним реестром `visual-12`; новой генерации нет.

## Приватная конфигурация после разрешения

Используются только существующие фиксированные пути D4: `.env`, `.env.sheets`, `.secrets/sheets-service-account.json`. Не выполнять `source`, не печатать содержимое. Формат переменных — в `.env.example` и `.env.sheets.example`. Нужны оба переключателя live. Приватные файлы — текущего владельца, обычные, 0600/0400, без symlink; каталог ключа — 0700/0500. Ключ RSA 2048–4096 бит, без пароля. Никаких ADC, поиска ключей, импорта из окружения или альтернативных путей.

Mac должен иметь `/usr/bin/openssl` и корректные системные часы. Новых Python-пакетов не требуется. Системный ключ подписи передаётся процессу через stdin/анонимный pipe, не аргументы и не временный файл. Открытый ключ, токен и JWT не показывать. Использование уже созданного ключа и адресатов согласовать с владельцем перед чтением.

## Изолированный реестр и команда

После явного разрешения подготовить **новый** приватный родительский каталог вне исходников. Его владелец — текущий пользователь, права строго 0700. Самого каталога реестра `run-01` ещё не должно быть. Ни старый smoke-реестр, ни VM-реестр не использовать.

Команда ниже — шаблон без секретов; путь заменить на согласованный абсолютный путь вне репозитория:

```sh
cd /Users/alex/myit/demo/Landing/d4-cleaning
.venv/bin/python -B tools/run.py --mac-demo-live --port 4344 \
  --registry-dir /ABSOLUTE/PRIVATE/D4-DEMO/run-01
```

Не добавлять `--submission-limit`: в этом режиме он запрещён, предел всегда одна новая заявка. Открыть `http://127.0.0.1:4344/`. Сервер слушает только loopback, один worker, без reload, proxy headers и access log. `--closed-live` по-прежнему требует настоящую D4-Debian12 и для этой съёмки не применяется.

## Кадры и действие

1. Открыть форму и показать пояснение **до кнопки**: какие сведения уйдут в тестовый Telegram и таблицу. Заполнить вымышленные поля, добавить одно безопасное фото и показать превью. Проверить маски на окнах Telegram/Sheets до начала записи.
2. Нажать сохранение **один раз**. Сначала показать «Запрос сохранён» и UUID, затем «Проверить квитанцию»: независимые статусы Telegram и Sheets. Подтверждение Telegram означает создание сообщения, не прочтение человеком; Sheets — сверку всех девяти значений.
3. Показать обработанное фото/параметры и тот же UUID в закрытом Telegram. В строке тестовой таблицы показать UUID, параметры, синтетический контакт и `photo_count`. Для корреляции достаточно одного и того же UUID в трёх местах; адреса ресурсов показывать не нужно.
4. Остановить запись. Остановить собственный сервер Ctrl+C. При необходимости открыть тот же реестр обычной командой без live-флага: это не отправляет задания. Квитанция доступна по ключу в открытой странице час; после перезагрузки страницы её ключ теряется. Реестр не является долговременным архивом: штатная очистка данных через 24 часа.

## Ошибка, неопределённость и завершение

При отказе, 429, сетевой ошибке или неизвестном исходе остановить демонстрацию. Не нажимать новую заявку, не запускать CLI доставки, не менять статусы SQLite, не создавать следующий реестр ради повтора. Возможная отправка/запись не повторяется автоматически. Каждый канал имеет собственный конечный результат; сбой одного не отменяет второй. После обрыва процесса начатая операция становится неизвестной, не начатая — отказом без отправки.

Владелец вручную проверяет чат/строку **по UUID** и решает дальнейшие действия. Не трактовать отсутствие ответа как отсутствие сообщения/строки. Повтор формы с прежними данными возвращает прежний номер; новая заявка сверх лимита отклоняется. Повторный live-запуск с тем же реестром отвергается до чтения конфигурации.

После согласованного завершения владелец отзывает временный доступ service account к таблице и временные права бота, решает судьбу тестового сообщения/строки и ключа. Ротацию/отзыв ключа, удаление реестра, файлов и внешних данных выполнять только по отдельной команде. В записи и передаче для `/work/` оставлять лишь согласованные обезличенные кадры; интеграция в витрину вне этого пакета.

## Публичный вариант

```sh
.venv/bin/python -B tools/serve.py --port 4351
```

Это статический preview `public/`, без SQLite, конфигурации и обработчика заявок. Данные/фото находятся в памяти открытой страницы; кнопка готовит текст, отдельная кнопка копирует его без фото. Перезагрузка очищает результат. JavaScript обязателен. Для стокового примера нужны только файлы того же сайта; внешних сервисов нет. Публикация этого варианта пока не выполняется.
