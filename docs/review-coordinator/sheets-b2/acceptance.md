## Предложение зависимостей — требуется пересмотр до установки

Набор из 8 новых пакетов с google-auth 2.43.0/rsa 4.9.1 не согласован.
Недостаток предложения: риск ограничен общей оговоркой о старом SDK, но Python-RSA официально
архивирована и больше не сопровождается. Это существенное свойство выбранной криптографической зависимости,
а не обнаруженная этой проверкой конкретная эксплуатация уязвимости D4.

Независимо прочитаны публичные PyPI JSON без скачивания wheel/установки:

- google-auth 2.62.1 действительно требует cryptography для CPython 3.11.
- cryptography 50.0.2 и 49.0.0 не имеют подходящих macOS Intel wheel в проверенных метаданных.
- cryptography 48.0.1 имеет подходящие universal2 wheel, но PyPI публикует advisories.
- rsa 4.9.1 имеет подходящий wheel, но описание проекта прямо сообщает об архивировании/прекращении сопровождения.

Точные данные: dependency-review.json. Отсутствие advisories в JSON не доказывает безопасность,
а опубликованные advisories сами по себе не доказывают применимость каждого сценария к D4.
Совместный resolver/import/runtime текущего предложения не запускались.

Вернуть исполнителю только пересмотр маршрута/предложения зависимостей:

1. Явно описать статус сопровождения RSA и разницу между wheel-совместимостью и пригодностью набора.
2. Сравнить актуальный Google SDK с актуальной cryptography в подходящей Linux-среде
   и вариант сборки актуальной cryptography для существующего Intel Mac.
   Указать точные версии/транзитивный набор, необходимые действия/инструменты и непроверенные предположения.
   Если иной поддерживаемый маршрут лучше — обосновать официальными источниками.
3. Дать рекомендацию для согласования среды; не считать Linux уже подготовленным/разрешённым.
   Не переносить проект, не ставить Docker/Rust/Homebrew, не собирать пакеты и не менять Python/venv автоматически.
4. Принятый офлайн-код не переделывать ради этой сверки, исторический lock и .env не менять.
   Установка/новая среда/ресурсы/credentials/live остаются отдельными решениями владельца.

В следующей разрешённой кодовой итерации также убрать слово append из пользовательского сообщения
о неизвестной записи: «повторная запись запрещена; доступна проверка результата».
Техническая терминология допустима в CLI/документах; клиентской квитанции достаточно смысла операции.
Это замечание редактуры, не блокер принятого офлайн-контракта.
