# D4 «Тихий дом» — прототип 02 и план зависимостей

06.11.2026. Этап визуального прототипа принят координатором в проверенном объёме, с оговоркой о нативной
клавиатуре select ниже. Ошибка разметки трёх списков закрыта. Сохранение/отправка и N4 целиком не приняты.

## Срез и независимая проверка формы

`d4-tihiy-dom-prototype-02`; 41/41 файлов manifest совпали.
SHA-256 `docs/manifest.sha256`: `658e1633087173bd54788e12355e10997c4b8abf40de9835c6ebc0ce70afd5e3`.
Код исполнителя не изменялся; результаты ревью исключены из авторского manifest.
Просмотрены переснятые filled-form-1440 и upload-focus-390.

Chrome 157.0.8103.38, имеющийся Playwright Core из QA D2. Сервер 4346 остановлен после проверки.
`r2/results.json`: 20/23 успешных утверждений. Три неуспешных — независимый выбор нативных select
клавишами: Click → Home → Down → Enter оставлял placeholder. Отдельная проба ArrowDown/Enter/Tab
тоже не изменила значения (`r2/keyboard-probe.json`). Это незакрытая проверка в доступном headless-инструменте,
не доказанный дефект исправленной HTML-разметки; авторский CUA-прогон не выдан за независимый.

В DOM все три варианта присутствуют. Для дальнейшего сценария они выбраны через selectOption:
«Прямой», «Два места», «Ткань / рогожка». Заполненная форма с синтетическим контактом и фото показывает
честное «не сохранена», не содержит aria-invalid, фокус на результате; возврат сохраняет три выбранных значения.
Tab из textarea приводит к photos; Enter вызвал настоящий file chooser, файл выбран и показан.
Нативный input прозрачен, область одна, focus-within даёт видимый outline.
Шесть ширин без overflow, пустая форма снова даёт шесть ошибок с фокусом на списке, pageerror отсутствуют.

Первый автоматический прогон без открытия select вызвал каскад отказов; он сохранён в `r2/attempt-01.json`.
В итоговом скрипте клавиатурная проба отделена от проверки формы с программным выбором.
Настоящий zoom 200%, VoiceOver, другие движки/устройства, префикс, сеть и полный WCAG не проверены.

## Проверка плана установки без установки

CPython 3.11.8, pip 24.0, macOS x86_64. Прочитаны официальные страницы точных релизов PyPI:
[FastAPI](https://pypi.org/project/fastapi/0.162.0/), [Pydantic](https://pypi.org/project/pydantic/2.14.3/),
[Uvicorn](https://pypi.org/project/uvicorn/0.54.0/), [python-multipart](https://pypi.org/project/python-multipart/0.0.33/),
[Pillow](https://pypi.org/project/pillow/13.0.0/), [pytest](https://pypi.org/project/pytest/9.2.0/),
[httpx](https://pypi.org/project/httpx/0.28.1/).

Выполнен pip с `--dry-run --ignore-installed --no-cache-dir --only-binary=:all:` и requirements-test.txt.
Это разрешение метаданных и загрузка wheel, не установка и не проверка импортов.
После запрета доступа из sandbox повторён сетевой dry-run через согласованный инструмент.
Результат exit 0: 7 прямых + 17 транзитивных, все 24 — готовые wheel для текущей платформы.
В частности, разрешены Pillow CPython 3.11 macOS x86_64 и pydantic-core соответствующей платформы.
Файлы/хэши и среда — `r2/dependencies-resolved.json`; точные версии — `r2/constraints-macos-py311.txt`.
`.venv` не создан, установленных пакетов этим действием не добавлено.

FastAPI транзитивно требует `opentelemetry-api==1.45.2`; это явно входит в рассмотренный набор.
Фразу автора «без телеметрии» нельзя трактовать как отсутствие пакета API в зависимостях.
SDK/exporter в разрешённом dry-run наборе нет; отсутствие самовольных внешних отправок проверять в реализации.
Заменять версии/добавлять extras или системную компиляцию при ошибке нельзя без согласования.

## Конкретный предлагаемый следующий шаг

После разрешения владельца исполнителю: отдельный `.venv` D4, установка семи прямых пакетов и их
зафиксированных 17 обязательных зависимостей, pip check, импорты и проверка декодирования JPEG/PNG/WebP.
Можно использовать constraints из папки ревью вместе с requirements-test.txt, чтобы не разрешать другой набор молча.
Затем локальный этап A задания 10: SQLite, безопасные фото, идемпотентность, квитанции,
тестовые адаптеры доставки, проверка отказов/перезапуска/очистки. Проверка solver не гарантирует работу установленного стека.
Передать фактический lock и результаты тестов. Telegram/Sheets/live-отправки, аккаунты, deploy и публикация не разрешаются.
Эта рекомендация координатора не заменяет разрешения владельца на установку и переход к серверной реализации.
