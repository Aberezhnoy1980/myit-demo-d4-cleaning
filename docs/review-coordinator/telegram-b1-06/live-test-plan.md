# План одной тестовой отправки D4

06.11.2026. Подготовлен для разрешения владельца; пока не выполнялся.
Получатель уже проверен: «myit D4 — тестовые заявки», бот @myit_d4_demo_bot.
ID и токен остаются только в приватной .env; live сейчас выключен.

1. Создать одну свежую заявку через локальный HTTP D4:
   sofa=Прямой, size=Два места, material=Не знаю,
   description=Синтетическая проверка Telegram D4, channel=email, contact=demo@example.test.
   Только технический однотонный JPEG live-test-photo.jpg (64×64, 692 байта,
   SHA-256 0df354408acdf52a0b82441231be23bd439cede17f08dd3f33b024c441c822d0).
   Сохранение/перекодирование — принятый локальный сервер. Квитанцию не печатать целиком.
2. Зафиксировать полученный UUID без receipt_key, остановить локальный сервер.
   Не выполнять simulate для этой заявки. Фото/контактов людей нет.
3. На время одной команды включить D4_TELEGRAM_LIVE=1 в .env и выполнить
   принятую CLI telegram-send для только что созданного UUID с --execute-live.
   Не более одного sendPhoto; при отказе/unknown не повторять автоматически.
   В finally вернуть LIVE=0 и проверить приватную конфигурацию.
4. Внешняя подпись продукта: «Демо D4 · запрос <UUID>»,
   «Диван: Прямой · Два места», «Обивка: Не знаю»,
   «Синтетическая заявка. Услуги не оказываются.»
   Контакт/описание/receipt_key не отправляются.
5. Проверить безопасный результат CLI и локальную квитанцию; API-успех не означает прочтения.
   Владелец подтверждает одно фото и тот же UUID в группе. Локальный сервер затем остановить.
6. Предлагаемый срок внешнего сообщения: владелец удаляет вручную после подтверждения,
   не позднее часа после теста. DeleteMessage не вызывать. Локальные данные/backup имеют прежний TTL 24 ч;
   этот тест не запускает отдельную очистку или изменение сроков хранения.

Нужное разрешение: указанная локальная заявка, временное включение live и один sendPhoto
в проверенную группу с этим JPEG/подписью, проверка квитанции и предложенный срок удаления владельцем.
Git, установки, Google и публикация не входят в операцию.
