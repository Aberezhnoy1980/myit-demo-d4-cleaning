Пять прямых серверных пакетов и два тестовых. Пакет `multipart` с другим именем не нужен.
SQLite, UUID/случайные ключи, хэши, файловые операции, multiprocessing/subprocess, таймауты,
время и очередь заданий обрабатываются стандартной библиотекой Python; отдельные pip-пакеты для них не нужны.
Используем обычные fastapi/uvicorn, без extras `[standard]` и без CLI/телеметрии/перезагрузчика.
ORM, Redis, Celery, SQLAlchemy, aiosqlite, JS/npm-пакеты, дополнительные браузеры и Google/Telegram SDK в этот список не входят.
Нужная локальному тесту изоляция файлов/DB обеспечивается временными каталогами; настройки — окружением без python-dotenv.

## Команда установки — только после отдельного разрешения

Запускать из D4, не из business и не из соседнего демо. Если `.venv` уже появится, сначала проверить его принадлежность D4.
Команды ниже в этой сессии не выполнялись:

```sh
cd /Users/alex/myit/demo/Landing/d4-cleaning
python3 -m venv .venv
.venv/bin/python -m pip --isolated install --index-url https://pypi.org/simple --only-binary=:all: -r requirements-test.txt
.venv/bin/python -m pip check
```

requirements-test.txt включает requirements-server.txt: одна установка содержит все семь прямых пакетов.
Для одного сервера без тестов вместо requirements-test.txt указывается requirements-server.txt.
`--only-binary=:all:` требует готовые пакеты wheel; компилятор/Rust/Homebrew или системные библиотеки не устанавливаются.
На PyPI есть Pillow 13.0.0 wheel для CPython 3.11 / macOS x86_64; установка/импорт здесь ещё не проверены.
Если разрешённая установка не сможет разрешить версии/найти wheel, остановиться и предложить согласованную замену;
не переключаться молча на компиляцию, другие версии или дополнительные установки.

## Транзитивные зависимости и проверка после разрешения

Перечислены все **прямые** зависимости. Pip также установит их обязательные зависимости, например Starlette/AnyIO,
pydantic-core, Click/h11, httpcore и служебные зависимости pytest. Их точные версии пока не разрешались и не фиксировались;
этот список не выдаётся за полный транзитивный lock. Расширенные наборы пакетов намеренно не запрашиваются.
После разрешения установки: pip check, импорты/декодирование трёх форматов, воспроизводимые API-тесты,
затем сохранить фактически разрешённый набор и версии в отдельном lock с учётом платформы.
Проверка метаданных не равна совместной проверке установленного стека.

Pillow сам по себе не делает загрузку безопасной: отдельно нужны лимиты тела/количества/пикселей,
изоляция декодирования с ограничением времени/памяти, закрытое хранение и проверка отказов.
Публичные фото/контакты и реальные внешние каналы по-прежнему запрещены без отдельного согласования.
