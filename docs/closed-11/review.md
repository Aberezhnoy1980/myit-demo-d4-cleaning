## Границы запуска

В обычном режиме `tools/run.py` сохраняет заявку в локальном SQLite. `--closed-live` добавляет проверку Debian 12
и имени `d4-debian12`, обоих переключателей live, нового каталога реестра и явного лимита от 1 до 200.
Каталог создаётся атомарно при старте. Лимит списывается под блокировкой после успешного commit SQLite
и учитывает также заявки, позже удалённые по сроку хранения. Заявка с тем же ключом и телом возвращает прежний номер
в пределах срока хранения и штатного ограничения частоты запросов.

Команда для отдельно согласованного запуска из каталога с этим срезом в VM, под пользователем `d4`.
Родитель `closed-runs` заранее подготовлен с правами `0700`, `run-01` ещё не существует.

```sh
/home/d4/d4-lab/.venv/bin/python tools/run.py --closed-live --port 4344 \
  --registry-dir /home/d4/d4-lab/closed-runs/run-01 --submission-limit 1
```

Слушатель `127.0.0.1:4344`, один процесс, журналы доступа отключены. `--registry-dir` без закрытого флага
открывает прежние квитанции и оставляет внешнюю доставку выключенной. Повторный закрытый запуск на том же каталоге
отклоняется до загрузки конфигурации. Файлы настроек `.env`, `.env.sheets` и фиксированный JSON service account
открываются только в явном закрытом режиме, без ADC, прокси из окружения или подстановок shell.
Живой прогон, чтение настоящих ключей и подтверждение получателей требуют отдельного согласования.

Перед кнопкой отправки форма показывает назначение данных по результату `/api/health`.
Закрытый режим называет обработанное фото, номер и параметры дивана для тестового Telegram,
а данные заявки с синтетическим контактом для тестовой Google-таблицы. Обычный режим сохраняет пояснение
о локальном сохранении. При смене режима в открытой вкладке форма обновляет пояснение и требует нового нажатия.
POST несёт режим, показанный при нажатии, в `X-D4-Delivery-Mode`. Сервер использует то же значение режима,
что и `/api/health`. При расхождении возвращает `409` с `delivery_mode` до чтения тела и расходования квоты.
Форма показывает актуальное пояснение, сохраняет поля, фото и ключ повтора, ждёт нового нажатия.
Заголовок обязателен в закрытом режиме. Прежние локальные клиенты могут сохранять заявку без заголовка.

## Доставка и восстановление

- Сохранение заявки, обработанного фото и двух `live_queued` выполняется в одной транзакции. После ответа с номером
  прежний фоновый обработчик берёт только эти два задания. Каждый адаптер принимает одно задание своего канала с `attempts=0`.
- Telegram выполняет один `sendPhoto` с JPEG из реестра, номером и параметрами дивана. Контакт и описание остаются вне сообщения.
- Sheets использует OAuth Google SDK с одним обменом и HTTPS без транспортных повторов и перенаправлений. Контракт B2
  проверяет шапку, ищет UUID, делает один RAW append и сверяет девять полей чтением. Ключ квитанции и фото в таблицу не передаются.
- После отказа или неопределённого исхода связанный обработчик завершает задание и переходит ко второму каналу.
  Обычное открытие реестра переводит прерванное ожидание в отказ, начатую живую попытку в неопределённый исход.
  Старые тестовые задания не переводятся в живые. Ручная обработка Telegram сохраняет прежний контракт, адресные команды Sheets остаются закрыты.

## Воспроизведение офлайн

Срез передан в `D4-Debian12` архивом из 34 файлов исходника, тестов, инструментов и пустых шаблонов.
SHA-256 `84798dad4ed971af5c2474bdb08aa713c15d7ad312061b8f455b1ec511e1f91e`.
Архив проверен перед распаковкой. Внутри VM используется подготовленное окружение `/home/d4/d4-lab`.

```sh
unshare --net -- setpriv --reuid=d4 --regid=d4 --init-groups \
  env PATH=/home/d4/d4-lab/node-bin:/usr/bin:/bin PYTHONDONTWRITEBYTECODE=1 \
  /home/d4/d4-lab/.venv/bin/python -m pytest -q -p no:cacheprovider tests
```

Команда выполняется из распакованного исходника с правами создать сетевое пространство.
Тесты передают синтетические приватные файлы штатному загрузчику, проверяют параметры слушателя при вызове Uvicorn
и перехватывают HTTPS на уровне `MockTransport`. Транспортные счётчики, подпись JWT, данные JPEG и строки проверяются
внутри тестов. Метки `live_*` в примерах означают проверенную ветку кода с подставными ответами.

| Сценарий | Проверяемый результат |
|---|---|
| Успешная форма | Одна попытка Telegram с обработанным фото, один RAW append с синтетическим контактом, сверка девяти полей. |
| 403 или 429 по одному каналу | Этот канал получает окончательный отказ, второй доставляет независимо. |
| Неопределённый исход | Потеря ответа Telegram или ответа после append, а также несовпадение поля при чтении дают `live_unknown`. |
| Повтор и перезапуск | Прежний UUID и прежняя квитанция, один вызов Telegram и максимум один append. Прерванные задания при старте завершаются локально. |
| Исчерпание квоты | При двух одновременных заявках и лимите 1 сохраняется одна. Очистка реестра квоту не восстанавливает. |
| Ограничения запуска | Другой хост, отсутствие лимита, неполная или выключенная конфигурация и ссылка на ключ отклоняются до запуска. |
| Разделение режимов | Тестовые задания не получают живого вызова, обычная форма сохраняется локально. |
| Утечки | В логах и ответах нет тестовых секретов, ID ресурсов и OAuth assertion. Ключ квитанции используется только для доступа к ней. |
| Пояснение до отправки | Ответ `/api/health` в каждом режиме даёт соответствующий текст до включения кнопки. Смена режима во время открытой формы обновляет текст без POST. Проверяется фактический `public/app.js` с DOM-моделью Node. |
| Смена режима между GET и POST | Сервер в обоих режимах отклоняет устаревший заголовок без заявки, фото, заданий, записи лимита или сетевых вызовов. Форма показывает режим из `409`. Следующее нажатие передаёт новый режим с тем же ключом повтора. |
