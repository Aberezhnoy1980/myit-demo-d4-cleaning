## Исправление

`public/app.js`, renderReceipt: вместо общего утверждения «Реальных отправок нет» при любом simulated-канале
выводится отдельное пояснение с именем каждого тестового канала:

> Google Sheets: тестовый режим. Реальная отправка по этому каналу не выполнялась.

Для Telegram в тестовом режиме используется то же пояснение с именем Telegram.
Заголовок сохраняет серверный смысл результата Telegram: создание сообщения с неподтверждённым прочтением
либо неизвестный исход с запретом повтора. Пояснение Sheets не делает выводов о Telegram.
Независимость каналов и существующая операция simulate сохранены; серверные исходники/статусы не менялись.

## Проверки

В tests/test_telegram.py добавлены 3 регрессионных случая. Используются временная SQLite, искусственные значения,
MockTransport и прежний запрет socket/DNS. Фактический renderReceipt из app.js исполняется Node VM
с минимальной моделью DOM: это проверка текста/логики, не новый визуальный браузерный прогон.

| Сочетание | Проверенный результат |
|---|---|
| Telegram live_delivered + Sheets simulated | Заголовок подтверждает создание сообщения, не прочтение; тестовое пояснение только у Sheets |
| Telegram live_unknown + Sheets simulated | Заголовок сохраняет неизвестный исход и запрет повтора; тестовое пояснение только у Sheets |
| Обычная тестовая квитанция Telegram + Sheets | Два отдельных именованных пояснения; живая доставка не подтверждается |

Для смешанных случаев до Sheets-имитации выполнен initialize; последующая arm_test_jobs/step(Sheets)
не меняет строку Telegram. Проверены все три итоговые квитанции, а не только отдельная функция текста.
Реальный `.env` не читается, вызовов Telegram нет. Никакие файлы/пробы ревьюера не запускаются и не меняются.
