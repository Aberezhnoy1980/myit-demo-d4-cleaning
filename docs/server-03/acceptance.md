# Серверный срез 03 — авторская проверка

06.11.2026 · `d4-tihiy-dom-server-03`. Передаётся для независимого ревью; статус «принято» не присвоен.
Вход: новое разрешение в задании 10; работа только в D4, без дополнительных агентов и живых каналов.
Установлены 24 разрешённых пакета, версии совпали с constraints. Фактический lock и environment.json переданы.

## Реализованный путь

Форма → ограниченное чтение multipart → проверка полей/синтетического контакта → проверка ключа повтора
→ отдельный декодер для каждого фото → одна транзакция SQLite (заявка, новые JPEG BLOB, два задания)
→ ограниченная квитанция своего запроса. Никакие внешние вызовы не удерживают HTTP-запрос: транспортов нет.

По умолчанию оба задания `not_connected`. Команда администратора может выполнить только TestAdapter с simulated=1.
Тестовые success/unavailable/rate_limit/timeout/forbidden проверяют состояния; они не доказывают Telegram/Sheets.
Реальный HTTP-транспорт, OAuth/токены, public deployment и публичный режим произвольных данных не созданы.

Все внешние socket.create_connection в тестовом процессе запрещены fixture. Это проверка локальной логики, не live-сервисов.

## Материальные ограничения

Реальные Telegram/Sheets не подключены и получения в них нет. N4 целиком не закрыт.
Не проверены настоящий browser zoom 200%, физический телефон, отдельные Chrome/Safari/Firefox, скринридер,
системное переключение reduced motion, отключение JS настройкой браузера и профиль медленной сети.
Отказ загрузки JS/медиа и отсутствие overflow проверены отдельно; viewport не выдаётся за zoom.
WCAG/публичную готовность по этому протоколу не заявляем.

Изоляция фото — дочерний процесс, не контейнер/OS sandbox. На этой macOS RLIMIT_DATA/AS отвергаются даже вне
командной песочницы. Вместо них ограничены пиксели, 3 с CPU, 6 с wall time и RSS 384 МиБ с выборкой 100 мс,
максимум два процесса. Между выборками возможен краткий перерасход памяти; отсутствие ps вызывает отказ, не обход ограничения.
Перед публичным/реальным приёмом эта граница и данные/доступы требуют отдельного ревью.

Очистка 24 ч выполняется при старте/каждые 60 с работающего приложения; при выключенном сервере — после запуска.
Backup очищается только административной командой. Lock содержит точные версии для одной платформы, не хэши дистрибутивов;
совпадение с 24 разрешёнными версиями подтверждено environment.json. Исходный reviewer JSON с URL/хэшами не изменён.
